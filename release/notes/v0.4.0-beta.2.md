This is an **experimental beta**, not a stable release, from
`feat/ps5-network-transfer`. It is a **source-only development milestone**.

**Downloadable application builds and the PS5 receiver ELF are not included.**
This release has no uploaded assets: only GitHub's automatically generated
**Source code (zip)** and **Source code (tar.gz)** archives are available.
v0.1.0 remains the latest stable release; its existing application downloads do
not include these beta features. The Python application/package version is
`0.4.0b2` (PEP 440), corresponding to release `v0.4.0-beta.2`.

## Changes since v0.2.0-beta.1

### PS5 LAN transfers

- CLI `transfer-ps5 --start-receiver` now reuses the GUI's SDK deployment and
  encrypted automatic startup pairing. It can build a missing/stale source-tree
  receiver with an already installed SDK, without downloading dependencies.
- GUI Receiver Manager Start/Stop, authenticated status and six-digit pairing
  remain available. An existing receiver is reused only with authenticated
  access; services are never silently replaced or restarted.
- Internal storage and USB0 destinations retain authenticated streaming,
  inventory/hash validation, private staging, existing-name refusal and safe
  atomic publication with explicit receipts. These safeguards were introduced
  in the previous beta and remain mandatory.
- Transfers show progress, smoothed speed/ETA, byte counts, duration, average
  speed and verification. Logs show the actual destination, and specific receiver
  errors retain their useful detail.
- The package's current folder name determines the LAN destination, including
  renamed existing packages. CLI `--name` provides an explicit override.
- Successful GUI sends return to the main window after OK and retain the local
  package. Failed sends retain the package for retry without rebuilding.
- **Physical PS5 transfer has been successfully tested, as reported by the
  project owner.** This does not establish every firmware, ELF loader, storage
  setup or Minecraft/mod configuration as compatible.

### GUI and packaging

- Collapsed Build advanced options, Transfer advanced options and Local package
  management keep the main instance → output → build → transfer workflow simpler.
- Corrected initial Connect to PS5 button sizing, restricted the divider tooltip
  to the draggable handle, and removed duplicate visible Fabric preparation text.
- Compatibility labels are **Works**, **Untested** and **Broken**. Detailed
  evidence and technical packaging blockers remain available; a successful build
  never creates a PS5 compatibility confirmation. Mod tracking records known
  issues only; an unlisted mod is not verified working.
- Reusable metadata-driven Vanilla/Fabric packaging resolves inheritance,
  dependencies, arguments, assets and matching Windows x64 Java runtimes.
  Verified local/cache runtimes are preferred. Missing runtime downloads default
  on, with offline/no-download controls retained.
- Native headless Fabric preparation runs automatically for GUI builds when
  actual metadata requires remapping. Native JDK discovery, matching-cache
  validation/reuse, existing-package preparation and manual `prepare-fabric`
  remain available. Vanilla and Fabric not requiring remapping bypass it.
- Vanilla Minecraft 1.20.1 and Minecraft 1.20.1 / Fabric Loader 0.20.1 with native
  preparation are owner-confirmed reaching the PS5 main menu. This establishes
  startup, not world loading or compatibility with every Fabric mod. The existing
  Minecraft 26.3 evidence is unchanged.

## Running from source and limitations

See [installation](https://github.com/isaacm0880/Minecraft-Playden-Packager/blob/v0.4.0-beta.2/docs/INSTALLATION.md),
[LAN transfers](https://github.com/isaacm0880/Minecraft-Playden-Packager/blob/v0.4.0-beta.2/docs/PS5_LAN_TRANSFER.md),
[automatic receiver startup](https://github.com/isaacm0880/Minecraft-Playden-Packager/blob/v0.4.0-beta.2/docs/PS5_RECEIVER_MANAGER.md#automatic-cli-startup)
and [compatibility evidence](https://github.com/isaacm0880/Minecraft-Playden-Packager/blob/v0.4.0-beta.2/docs/COMPATIBILITY.md).

- LAN deployment requires a **compatible, already-running PS5 ELF loader**. The
  packager does not start the loader. Automatic pairing requires forwarded
  payload output; otherwise use explicit manual `--pair` with an externally
  started receiver. No insecure automatic-pairing fallback is provided.
- **The receiver ELF is not bundled.** Build it locally using an installed PS5
  Payload SDK and deployment utilities, or explicitly allow the startup action
  to build it when needed. Credentials remain in memory; closing the local SDK
  connection does not request remote receiver shutdown.
- Some Minecraft configurations and mods remain untested. Forge remains blocked;
  NeoForge and Quilt launch packaging are unsupported. Java 8 packaging remains
  blocked by the preserved launcher argument-file requirement. Native Fabric
  preparation needs a host JDK 17+ with the compiler module, separate from the
  Windows Java runtime shipped inside a user's generated game package.
- LAN performance optimisation remains under investigation. FTP is not enabled;
  there is no measured PS5 FTP performance claim.
- Use a trusted private LAN: transfer contents are authenticated but not encrypted.
  Pairing has regression coverage but has not had an independent cryptographic
  audit. Windows SDK/loader acceptance and macOS source support remain limited.
- This is an experimental beta. Broader desktop, firmware/loader, game/world/mod
  and storage durability testing remains necessary.
